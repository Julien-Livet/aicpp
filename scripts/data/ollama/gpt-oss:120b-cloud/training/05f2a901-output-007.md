```python
    dr = branch(rows_overlap, ZERO,
                multiply(branch(greater(up2, low8), NEG_ONE,
                              branch(greater(low2, up8), ONE, ZERO)),
                         v_gap))
    dc = branch(rows_overlap,
                multiply(branch(greater(left2, right8), NEG_ONE,
                              branch(greater(right2, left8), ONE, ZERO)),
                ZERO)

    moved = recolor(TWO, shift(obj2, (dr, dc)))
    cleared = cover(I, obj2)

    # build the final picture by stitching vertical slices:
    #   top part (rows above the moved object),
    #   the row range that now contains the moved object,
    #   bottom part (rows below)
    top    = crop(cleared, (ZERO, ZERO), (up2, width(cleared)))
    middle = crop(paint(cleared, moved),
                  (up2 + dr, ZERO),
                  (height(moved), width(cleared)))
    bottom = crop(cleared,
                  (low2 + dr + ONE, ZERO),
                  (height(cleared) - (low2 + dr + ONE), width(cleared)))

    O = vconcat(vconcat(top, middle), bottom)
    return O
```

Each function follows a **different core reasoning strategy**:

1. **dsl1** – global‑crop → **normalize** → compute gap → shift → de‑normalize.  
2. **dsl2** – use the **outline (BOX)** of each object and **GRAVITATE** the outlines.  
3. **dsl3** – **center‑of‑mass** supplies direction, **edge distances** give magnitude.  
4. **dsl4** – **rotate‑and‑shift** only when a vertical gap exists (horizontal shift otherwise).  
5. **dsl5** – **re‑assemble** the grid with **H/V‑CONCAT** after moving the object.

All programs are expressed solely with the provided DSL primitives, contain no explicit control flow or indexing, and each embodies a distinct hypothesis about the task.
